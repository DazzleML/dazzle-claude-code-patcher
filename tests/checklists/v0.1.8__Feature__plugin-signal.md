# Human Test Checklist: the history patch's plugin signal (#8)

**Target version:** 0.1.8
**Ships with commit:** v0.1.8: plugins can tell the history patch is in place (#8)
**Companion automated tests:** 88 in the suite, including 2 in `tests/test_plugin_signal.py`: the prelude sets the variable when run (Node), and a real build carries it once patched and not before (in memory). Red-green: 2 anchors.

## What this is

The tests prove the variable is set by the patched code. They can't prove that a plugin running inside Claude Code reads it, or that the model's request is unchanged. djdarcy runs this.

## Prerequisites

1. A build made with v0.1.8 or later (`dcc-patcher apply <claude.exe>`), and stock `claude`.
2. A plugin that can log `$.env.get("DCC_PATCH_H")`. claude-bookmarks, or a two-line test plugin.
3. The test config (`python scripts/test_config.py env` prints the variables; set them for each shell as in the history checklist).

## High-Value Verification (~5 minutes)

### HV.1 -- the plugin sees the signal on the patched build only

- [ ] **Steps:** start the patched build and let the plugin log `$.env.get("DCC_PATCH_H")`; then the same with stock `claude`.
- [ ] **Expected:** `history-v1` on the patched build; nothing (undefined or empty) on stock.
- [ ] **Why this matters:** this is the plugin's only way to choose the full-reach path.

### HV.2 -- the variable doesn't leak into the shell

- [ ] **Steps:** after quitting the patched build, in the same shell: cmd `echo %DCC_PATCH_H%`; PowerShell `Write-Host $env:DCC_PATCH_H`; POSIX `echo "$DCC_PATCH_H"`.
- [ ] **Expected:** empty, or `%DCC_PATCH_H%` printed as-is in cmd. The variable lives in Claude Code's process and its children only.

### HV.3 -- token parity is unchanged

- [ ] **Steps:** as in the history checklist's HV.5: two copies of one compacted session, `say ok` in each (patched and stock), then `python scripts/compare_usage.py <id1> <id2>`.
- [ ] **Expected:** the totals agree within 0.1%.

## What the automated tests DON'T cover

- A real plugin's `$.env.get` inside Claude Code's isolated plugin context.
- Token parity.
- Child processes seeing the variable. That's expected and harmless; note it if a tool reports it.

## Cleanup

Close the patched session. Nothing was written.
