# Human Test Checklist: the walk crosses a compaction whose preserved messages were written after the summary

**Target version:** 0.2.5
**Ships with commit:** v0.2.5 (TBD)
**Companion automated tests:** 202 in the suite; new in v0.2.5: `tests/test_history_walk.py` (10: the shipped JavaScript run under Node on four synthetic session shapes). Red-green: `tests/one-offs/history_walk_v0.2.5/redgreen_v0.2.5.py` (2 mutants, 5 anchors / 5 guards, restored byte for byte).

## What this is

The automated tests prove the helper and the walker fragment do the right thing on small maps shaped like the real files. They can't prove that Claude Code's own loader hands the walker those maps, that the screen draws what the walk reaches, or that the model's request is unchanged. One live resume settles all three, and only the maintainer can run a patched build.

## Prerequisites

1. A build made with v0.2.5 (`dcc-patcher apply %USERPROFILE%\.local\bin\claude.exe`, then `dcc-patcher use patched`; `dcc-patcher status` names it).
2. A session with a late-segment compaction. On the maintainer's machine: `b0a3c966` (the SIMPLE-AI-TAG-TOOL session, 4 compactions, 7,347 messages). `tests/one-offs/history_walk_v0.2.5/scan_heads.py` lists others.
3. Nothing here writes anywhere but the session's own file (the resume appends to it, as every resume does).

## High-Value Verification (~5 minutes)

### HV.1 -- the resume reaches the first prompt (AC4)

- [ ] From `C:\code`, resume the session (`claude --resume b0a3c966-2bff-43b5-82dd-33e0cf746d3a`, or reopen it the way you did before).
- [ ] The banner reads `Dazzle Claude Code v2.1.296 · dcc 0.2.5`.
- [ ] `Ctrl+Home` (or scroll to the top): the first row is the first prompt of 2026-10-01, not `Compact summary`.
- [ ] Scrolling down, four `Compact summary (ctrl+o to expand)` rows appear, each where its compaction happened (the compaction rows patch R draws).
- [ ] The context indicator after the resume is about what it was on the v0.2.4 resume (the model's request is cut at the last compaction separately; this change doesn't touch it).

Expected before the fix: the top row is `Compact summary`, then "What you saw looks right except for beard".

### HV.2 -- a session resumed right after an idle compaction

- [ ] Resume `824abdef` (in `C:\code\dazzle-boorudatasettagmanager`) or `18ba9d65`: both end with the compaction summary as their newest message.
- [ ] The scrollback reaches the rows from before that compaction (before the fix it stopped at the preserved tail of the summary).

### HV.3 -- `check` on the originals

- [ ] `dcc-patcher check` on each original in the builds folder, 2.1.278 to 2.1.296: patch H reports every edit `APPLIES`, including `walker: cross a compaction boundary; at a relinked head, continue where the prune recorded`. (Run on 2026-10-11 against all 13: green.)

## What mocks don't cover

- The loader's own handling of a 70 MB file (the pre-parse walk, the 5 MiB skip) on the real build.
- The screen: whether 12,000 reached rows render and scroll acceptably.
- The request size: whether the API cut still happens at the last compaction with the longer display chain in memory.
- A session that was rewound and then compacted: rule 4 may continue from an abandoned branch's last row (documented in the design's ledger; nobody has seen it yet).
