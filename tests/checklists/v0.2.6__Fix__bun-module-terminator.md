# Human Test Checklist: a patched 2.1.308 or 2.1.309 starts (the NUL after a replaced module)

**Target version:** 0.2.6
**Ships with commit:** v0.2.6 (TBD)
**Companion automated tests:** 206 in the suite; new in v0.2.6: four in `tests/test_containers_pe.py` (a replacement whose length leaves a remainder of 0, 1 or 7 modulo 8 is NUL-terminated; `verify` refuses an image whose replaced module is not). Written before the fix: the remainder-0 case and the `verify` case were red on v0.2.5, green after.

## What this is

Claude Code 2.1.308 and 2.1.309 are compiled with a Bun that checks, at startup, that a NUL byte follows every module's embedded JavaScript. v0.2.5 wrote that NUL only as alignment padding, so a replaced module whose new length was a multiple of 8 had none, and the build exited with `error: An internal error occurred (Corrupted module graph: module contents are out of range)`. The automated tests prove the container now writes the NUL and that `verify` checks it. A replica of Bun's check (`tests/one-offs/bun_nul_terminator_v0.2.6/bun_graph_check.py`) passes on the v0.2.6 build of 2.1.309 and names module 824 on the v0.2.5 build. Only a real start proves Bun agrees, and only the maintainer runs a patched build.

## Prerequisites

1. Claude Code 2.1.308 or 2.1.309 installed (`~/.local/bin/claude.exe`); 2.1.309 on the maintainer's machine on 2026-10-22.
2. The v0.2.6 checkout (the launcher imports it: an editable install).

## High-Value Verification (~2 minutes)

### HV.1 -- the launcher rebuilds and the build starts

- [ ] Run `claude --version` from any shell. If the build was not already rebuilt, one line first: `dcc: dcc-patcher updated; building the patched copy... done; now running claude-dcc-2.1.309+dcc0.2.6.exe`.
- [ ] The output is `2.1.309 + dcc 0.2.6 (Dazzle Claude Code)`, not the `Corrupted module graph` error.
- [ ] Run `claude`: the banner reads `Dazzle Claude Code v2.1.309 · dcc 0.2.6`, and the session starts.

Expected before the fix: the error line above after the build line, exit without a session. (Observed by the maintainer on 2026-10-22 with `claude-dcc-2.1.309+dcc0.2.5.exe`.)

### HV.2 -- `verify` guards the terminator

- [ ] `python -m pytest tests/test_containers_pe.py -q`: 7 pass.

### HV.3 -- the replica agrees with Bun

- [ ] `python -I tests/one-offs/bun_nul_terminator_v0.2.6/bun_graph_check.py <builds>\claude-dcc-2.1.309+dcc0.2.6.exe`: `ok`.
- [ ] The same on `claude-dcc-2.1.309+dcc0.2.5.exe`, if still kept: `module contents are out of range (module 824 ...)`, the module Bun named by its error.

## What mocks don't cover

- Bun's own check runs in the real process; the replica covers the per-module part and not the optional records after the module table (the patcher never moves those).
- A later Claude Code may be compiled with a Bun that carries the upstream revert; the NUL is still what Bun's writer produces, so the fix stays either way.

## Cleanup

Nothing to undo. The v0.2.5 build of 2.1.309 in the builds folder can be removed with `dz safedel` once the v0.2.6 build has started.
