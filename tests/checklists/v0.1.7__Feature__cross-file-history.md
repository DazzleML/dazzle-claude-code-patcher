## What this is

Patch J lets a conversation that continued into a new session file scroll back into the file it came from. The automated tests prove the search logic on made-up files and that the patch applies. They can't run Claude Code on a real continued pair, measure the cost, or confirm the model's request is unchanged. This checklist does those things, on **copies** in the test config. djdarcy runs it.

## Prerequisites

1. **A continued pair:** a session whose file opens with a compaction boundary pointing into an earlier session's file. A session continued after running out of context is one; a fork is another.
2. **A build with J:** `dcc-patcher apply %USERPROFILE%\.local\bin\claude.exe` (it writes to the builds folder), or the `claude` launcher from v0.1.6.
3. **The test config, in every terminal used here:** `python scripts/test_config.py env` prints the two variables.
   - **cmd.exe:** `set CLAUDE_CONFIG_DIR=%LOCALAPPDATA%\dazzle-claude-code-patcher\test-config` and `set DISABLE_AUTOUPDATER=1`
   - **PowerShell:** `$env:CLAUDE_CONFIG_DIR = "$env:LOCALAPPDATA\dazzle-claude-code-patcher\test-config"; $env:DISABLE_AUTOUPDATER = "1"`
   - **POSIX:** `export CLAUDE_CONFIG_DIR="$LOCALAPPDATA/dazzle-claude-code-patcher/test-config" DISABLE_AUTOUPDATER=1`
4. **Copy both files:** `python scripts/test_config.py copy <child .jsonl>`, then the same for the parent. The originals are only read. A copy keeps every message's uuid (only `sessionId` is rewritten), so the child's link still matches the parent copy.
5. **J searches the copy's own folder.** Each copy lands in `test-config\projects\<the original's folder name>`. If the two originals are in different project folders, so are the copies; see 2.2.

**Reset:** delete only the copies you made, with `dz safedel <path>` (any shell), never the originals.

## High-Value Verification (~10 minutes)

### HV.1 -- the continued copy scrolls back into its parent

- [ ] **Steps:** from the session's own working folder, `<build> --resume <child copy id>`, then Ctrl+O and Ctrl+Home.
- [ ] **Expected:** the top shows the parent's first message (stock and H-only builds stop at the child file's first line, its compaction boundary).
- [ ] **Why this matters:** this is the whole feature; bookmarks into the earlier file depend on it.

### HV.2 -- the model's request is unchanged

- [ ] **Steps:** make a second copy of the child; send `say ok` in one copy with the J build and in the other with stock `claude`; then `python scripts/compare_usage.py <id1> <id2>`.
- [ ] **Expected:** the totals agree within 0.1%.
- [ ] **Why this matters:** J must change only what can be scrolled, never what the model is sent.

### HV.3 -- load cost

- [ ] **Steps:** time the start of each resume, from Enter to the first screen, J build vs stock: a stopwatch, or PowerShell `Measure-Command { <build> --resume <id> --print "ok" }`.
- [ ] **Expected:** note both numbers and the two files' sizes. J adds one more read of the child file and a read of the parent file.

### HV.4 -- a missing parent loads like stock

- [ ] **Steps:** `dz safedel` the **parent copy** only, then resume the child copy with the J build.
- [ ] **Expected:** the session opens normally and scrolls back as far as the child file's start. No error, no blank screen, no hang.

## Section 2: edges

### 2.1 -- a grandparent

- [ ] If you have a chain of three (a continuation of a continuation), copy all three. Ctrl+Home should reach the oldest file's first message.

### 2.2 -- a pair in two project folders

- [ ] If the parent lives under a different project folder, copy both and resume the child. **Expected today:** the walk stops at the child file's start, because J searches only the child's folder. Note it: that tells us whether a wider search is worth adding.

## What the automated tests DO cover

| Area | Count |
|---|---|
| the parent loaded up to the linked message, and no further | 1 |
| a grandparent reached through the parent | 1 |
| a missing parent, a missing file, a damaged line | 1 |
| H and J applying together to the real build, in memory | 1 |
| every file that names ojura credits it | 1 |

## What the automated tests DON'T cover

- Claude Code actually loading a real pair, and the scroll in the UI.
- The model's request (token parity).
- The time it costs on real files, and with many sessions in one folder.
- Pairs whose files are in different project folders.

## Cleanup

`dz safedel` the copies you made (`python scripts/test_config.py list` shows them), then unset the variables: cmd `set CLAUDE_CONFIG_DIR=` and `set DISABLE_AUTOUPDATER=`; PowerShell `Remove-Item Env:\CLAUDE_CONFIG_DIR, Env:\DISABLE_AUTOUPDATER`; POSIX `unset CLAUDE_CONFIG_DIR DISABLE_AUTOUPDATER`.
