# Human Test Checklist: compaction rows in the normal view; the launcher rebuilds when dcc-patcher changed

**Target version:** v0.2.2
**Ships with commit:** v0.2.2: compaction rows in the normal view; the launcher rebuilds when dcc-patcher changed
**Companion automated tests:** 131 in the suite. New for this version: `tests/test_launcher.py` (1: a build made by an older patcher is rebuilt at the next start, an anchor) and `tests/test_spec.py` (1: patch R loads as one display-only edit, a fence). `tests/test_check.py`'s real-build test runs every bundled patch, R included, against the local `claude.exe`. Red-green: `tests/one-offs/redgreen_v0.2.2.py`.

## What this is

Two things shipped. Patch R lets the normal screen draw a compaction summary where it happened, as the transcript (Ctrl+O) does, so both views of a resumed session start on the same first row. The launcher now rebuilds when the installed dcc-patcher is newer than the one that made the current build, so a new patch reaches `claude` without waiting for a Claude Code release. The automated tests prove the edit applies and the launcher's rule; they can't show a row in a terminal or a rebuild at a real start. A person does that here, on a session that has at least one compaction. Two of the steps were already seen live on 2026-10-09 (2.1.295 + dcc 0.2.2); they are marked.

## Prerequisites

1. dcc-patcher v0.2.2 installed and set up (`dcc-env`), on Windows, with Claude Code 2.1.278 or later.
2. A session with at least one compaction to resume. Your own long session is fine: nothing here writes to it; `--resume` only reads. The steps that change state (HV.4, section 3) touch only the builds folder and `launcher.json`.
3. **State isolation:** no `~/.claude` file is written. `CLAUDE_CONFIG_DIR` is used in section 2.3 only, pointed at a scratch folder.
4. Reset: `dcc-patcher use patched` returns the launcher to its default after section 3.

## High-Value Verification (~5 minutes)

**If you only have 5 minutes**, run these six.

### HV.1 — The normal view starts on the compaction summary (seen live 2026-10-09)

Validates: patch R, on the first row of a resumed session.

- [ ] **Steps:** `claude --resume`, pick a session that has a compaction at its start (one continued from an earlier session). Press `Ctrl+Home`. Then `Ctrl+O`, `Ctrl+Home`.
- [ ] **Expected:** the normal view's first row is `● Compact summary (ctrl+o to expand)`; the transcript's first row is the same `Compact summary`, with the summary text under it.
- [ ] **Why this matters:** this is #7's first criterion, the row the two views used to disagree on.

### HV.2 — Every compaction the history walks past shows the line

Validates: the filter change applies to every compaction summary, not only the first.

- [ ] **Steps:** in the same session, scroll down from the top through the whole history (`PageDown`, or search for `Compact summary`). Count the lines.
- [ ] **Expected:** one `● Compact summary (ctrl+o to expand)` line at each compaction; the count matches the compactions in the session file (for the maintainer's session: five). The model's re-read rows (`Read N files`) follow each one, as before.
- [ ] **Why this matters:** a bookmark or a search that lands between compactions must see the boundary it crossed.

### HV.3 — Ctrl+O shows the text; Ctrl+O comes back

Validates: the row's hint means what stock means by it.

- [ ] **Steps:** with the cursor on a `Compact summary` row, press `Ctrl+O`; read; press `Ctrl+O` again.
- [ ] **Expected:** the transcript view opens on the same row with the summary's text ("This session is being continued from a previous conversation...") under it; the second `Ctrl+O` returns to the normal view at the same place. There is no in-place fold (that's #10).
- [ ] **Why this matters:** the line promises the text is one key away.

### HV.4 — A newer dcc-patcher rebuilds at the next start (seen live 2026-10-09)

Validates: the launcher's new rule.

- [ ] **Steps:** with a build made by an older version current (`dcc-patcher use` shows `current: claude-dcc-<cc>+dcc<older>.exe`), install the newer dcc-patcher (`pip install --upgrade dazzle-claude-code-patcher`, or in a checkout, bump the version and `pip install -e .`). Then:
  ```
  claude --version
  dcc-patcher use
  ```
  and list the builds folder (`dir "<builds>"` in cmd, `Get-ChildItem "<builds>"` in PowerShell, `ls <builds>` in Git Bash).
- [ ] **Expected:** `claude --version` prints `dcc: dcc-patcher updated; building the patched copy... done; now running claude-dcc-<cc>+dcc<new>.exe` on stderr (about three seconds), then the new version line. `dcc-patcher use` shows the new build as `current`. The older build is still in the folder.
- [ ] **Why this matters:** without it, a new patch sits unused until Anthropic ships.

### HV.5 — `check` reports R

- [ ] **Steps** (same in every shell): `dcc-patcher check %USERPROFILE%\.local\bin\claude.exe` (cmd) / `$HOME\.local\bin\claude.exe` (PowerShell) / `~/.local/bin/claude.exe` (Git Bash).
- [ ] **Expected:** `R  applies` with `APPLIES x1  prompt-screen row filter: keep compaction summaries`, beside the other patches; exit 0.
- [ ] **Why this matters:** the edit must be found exactly once, or the patch is not applied.

### HV.6 — Token parity (optional; by construction)

Validates: the model receives the same request as stock.

- [ ] **Steps:** copy a compacted session under the test config (`scripts/test_config.py`, `scripts/copy_session.py`), resume the copy once with `claude-stock` and once with `dazzle-claude`, then `scripts/compare_usage.py`.
- [ ] **Expected:** the request sizes agree within 0.1%.
- [ ] **Why this matters:** the filter runs when the screen is drawn, after the request is built, so parity holds by construction; this step is the measurement if anyone doubts it.

## Section 1: The row (~3 min)

### 1.1 A bookmark lands on a compaction summary (#7, criterion 3)

- [ ] **Steps:** with claude-bookmarks installed, place a mark on a `Compact summary` row (or `$.ui.scroll` to its uuid from the bookmarks list), scroll away, jump back.
- [ ] **Expected:** the normal view lands on the row. Before v0.2.2 there was no row to land on.

### 1.2 The live compaction

- [ ] **Steps:** let the session compact (or wait for an idle compaction), then scroll to that point in the normal view.
- [ ] **Expected:** stock's own notice (`● Compacted while idle, before the prompt cache expired`, or the "Conversation compacted" line) and the new `Compact summary` line both appear; nothing is drawn twice.

### 1.3 Other transcript-only rows stay hidden

- [ ] **Steps:** compare the normal view and the transcript around a few tool calls and a `Skills restored` line.
- [ ] **Expected:** the normal view gained the compaction rows and nothing else; meta rows and the collapsed tool groups are as they were in v0.2.1.

## Section 2: The launcher (~3 min)

### 2.1 Same patcher, no rebuild

- [ ] **Steps:** `claude --version` twice.
- [ ] **Expected:** no `building` line the second time; the same build runs.

### 2.2 Claude Code updated and patcher updated at once

- [ ] **Steps:** after a Claude Code update and a dcc-patcher upgrade, `claude --version`.
- [ ] **Expected:** one rebuild line, `Claude Code updated` taking precedence in the wording, and a build named for both new versions.

### 2.3 A test config never rebuilds

- [ ] **Steps** (pick your shell):

  **cmd.exe**:
  ```cmd
  set CLAUDE_CONFIG_DIR=%TEMP%\dcc-test-config
  claude --version
  set CLAUDE_CONFIG_DIR=
  ```

  **PowerShell**:
  ```powershell
  $env:CLAUDE_CONFIG_DIR = "$env:TEMP\dcc-test-config"
  claude --version
  Remove-Item Env:\CLAUDE_CONFIG_DIR
  ```

  **POSIX (Git Bash)**:
  ```bash
  export CLAUDE_CONFIG_DIR=/tmp/dcc-test-config
  claude --version
  unset CLAUDE_CONFIG_DIR
  ```
- [ ] **Expected:** with a build made by an older patcher current, the launcher runs stock and says the test config is why; `launcher.json` is unchanged.

## Section 3: Rollback (~1 min)

### 3.1 Pin the previous build and come back

- [ ] **Steps** (same in every shell):
  ```
  dcc-patcher use claude-dcc-2.1.295+dcc0.1.11.exe
  claude --version
  dcc-patcher use patched
  claude --version
  ```
- [ ] **Expected:** the pinned build runs (no `Compact summary` rows in a resumed session, no rebuild line); `use patched` returns to the newest build without a rebuild, since it is already current.

## What the automated tests DON'T cover

- **The drawn row** in a real terminal: wording, the bold, its place among the re-read rows.
- **Scrolling reach**: that every compaction in a long session gets its row, not only the first.
- **The rebuild at a real start**: the timing (about three seconds) and the one-line message as a user reads it.
- **Token parity**, which holds by construction and is measured only by HV.6.
- **A bookmark landing**, which needs claude-bookmarks.

## Reporting issues found

1. Note the step and the shell.
2. Capture the exact command and output, and `dcc-patcher use`.
3. File an issue referencing this checklist and v0.2.2; for the row itself, #7.

## Cleanup

```
dcc-patcher use patched
```

Unset `CLAUDE_CONFIG_DIR` if section 2.3 was run (the steps do).
